# Desktop design system

Hyprland + Noctalia following macOS for surface, bar and typography, with
color, shape, spacing and motion from Material 3 (M3). This document says what
each visual decision is, where it lives and how to bring a new app into the
system.

## Principles

1. **Each axis has one owner.** Color, shape, spacing and motion follow M3.
   Surface, depth, bar and typography follow macOS. Mixing the two on the same
   axis is what makes the result incoherent.
2. **Color signals focus and action, not decoration.** `primary` shows up on
   the focused window, the selected item and the main button. Everything else
   is surface.
3. **One value, one place.** Every token has a single source. Hand-written
   config consumes the token and never copies the value.
4. **Nothing bounces.** Motion is fast and settles without overshooting.

| Axis | Owner | Summary |
|---|---|---|
| Color | M3 | Color roles generated by Noctalia |
| Surface and depth | macOS | 1px hairline, soft shadow, everything opaque |
| Shape | M3 | Short radius scale, coherent nested corners |
| Spacing | M3 | 4px grid |
| Typography | macOS | Inter in the role of SF Pro, mono only for code |
| Bar | macOS | Menu bar: straight, full width, hairline only at the bottom, no shadow |
| Motion | M3 | M3 curves and a critically damped spring |
| Icons | Papirus | Papirus-Dark in apps, Tabler in the shell |

## Color

The palette comes from Noctalia (default `[theme]` in
`hyprland/noctalia/settings.toml`, each machine's choice in its state file),
either from the wallpaper or from a ready-made scheme. What the system fixes
is the **roles**, not the values:
changing the palette in the Noctalia UI has to change the whole desktop
without editing any file.

| Role | Use |
|---|---|
| `primary` | Focus and action: selected item, main button |
| `secondary` | Secondary emphasis: active group, second chart color |
| `surface` | Window, panel and terminal background |
| `on_surface` | Text and hairlines on `surface` |
| `error` | Error and destructive action |

Dark mode only (`[theme] mode = "dark"`), like the fixed dark macOS. Surfaces
are tinted, not pure black (`pure_black_dark` off). M3 uses tone to separate
planes (`surface` < container), and pure black erases that hierarchy.

How each app gets the palette:

- **Noctalia template** (`theme.templates` in `settings.toml`): GTK 3/4,
  Hyprland, Ghostty, btop, cava and the community ones (herdr-app). Noctalia
  rewrites the generated files on every palette change; they stay out of git.
- **Hyprland**: does not use the palette. The window border is white with
  alpha (`borders.lua`), like the neutral macOS hairline.
- **Terminal tools** (nvim, fzf, tmux, starship): use the terminal's ANSI
  colors, which come from the terminal theme (herdr-app or Ghostty). Color in
  them is an ANSI index (0 to 15), never hex.

Exceptions: the shadow is black with alpha (`look.lua`) and the window border
is white with alpha (`borders.lua`), in any palette.

## Surface and depth

| Level | What | Treatment |
|---|---|---|
| 0 | Wallpaper | Nothing |
| 1 | Window | 1px hairline + shadow (radius 28, offset 0,6) |
| 2 | Bar, panel, launcher, notification, OSD | Solid: opaque background in the palette color + shadow |

- **Window border**, in `borders.lua`: colorless, as on macOS. Focused is white
  at 25% (`40`), unfocused is white at 8% (`14`). Focus reads through the
  hairline step, the larger shadow and `dim_inactive` (0.08) on the others.
- **Shadow**: alpha 0.35 across the whole system. Focused window `0x59000000`
  in `look.lua` (0x59 ≈ 0.35), and the shell with `[shell.shadow] alpha = 0.35`
  in Noctalia. An unfocused window drops to `0x33000000`, so the focused one
  looks closer.
- **No transparency or blur**, not even in the shell: screen color comes only
  from the palette, and text never sits on top of text. In Noctalia,
  `background_opacity = 1.0` on the bar and the OSD,
  `settings_window_translucent = false` in `[shell]` and `transparency_mode`
  at the default (`"solid"`, which Noctalia omits from the file). In Hyprland,
  `blur = { enabled = false }` in `look.lua`.

## Shape

Radius scale: `0 · 4 · 8 · 12 · 16 · 28`. No radius outside it.

| Element | Radius |
|---|---|
| Window | 12 with `rounding_power = 2.5`, which pulls toward the continuous macOS corner |
| Noctalia panels | Noctalia's internal scale (`corner_radius_scale` at the default 1.0) |
| Lock screen login box | 12, field 6 |
| Bar | 0: straight, full width, flush with the top, like the macOS menu bar |

Rules:

- **Touching the screen edge means no convex corner on that side.** The bar
  spans the full width and stays straight.
- **Every surface has the neutral 1px hairline**, the same as the unfocused
  window (panels: `[shell.panel] borders`). Only the focused window gets the
  `primary` hairline. On the bar the hairline is only at the bottom, with no
  shadow, like the macOS menu bar: Noctalia does not control the border per
  side, so `margin_edge = -1` and `margin_ends = -1` push the top and side
  hairlines 1px off screen.
- **Panels drop right below the bar.** Control center, session, wallpaper and
  clipboard float at `top_center`. The launcher and the polkit dialog open in
  the center of the screen.
- **Border color in Noctalia only accepts a theme role or hex.**
  `outline_variant` is not accepted, and an invalid value makes Noctalia
  discard the whole `settings.toml` and go back to the default bar. Run
  `noctalia config validate` after editing the file by hand.
- **Nested corner**: inner radius = outer radius minus the padding between the
  two. A radius 16 card with padding 8 gets a radius 8 button.

## Spacing

4px grid. Every spacing is a multiple of 4.

| Where | Value |
|---|---|
| Between windows (`gaps_in`) | 4, and the visible space between two windows is 8 |
| Window to screen edge (`gaps_out`) | 8 |
| Terminal padding | 16 horizontal, 12 vertical |
| Bar | height 38 (37 visible, the notch MacBook menu bar), padding 16, space between widgets 12 |

## Typography

The family lives in one place:
`desktop/fonts/50-fonts.conf` makes `sans-serif` resolve to **Inter** and
`monospace` to **JetBrainsMono Nerd Font**. Apps ask for the generic name:

| App | Asks for |
|---|---|
| GTK 3/4 (`settings.ini`) | `Sans 10` |
| libadwaita apps (gsettings, applied by `.dotter/post_deploy.sh`) | `Sans 10` and `Monospace 10` |
| Qt | Follows GTK (`QT_QPA_PLATFORMTHEME=gtk3`) |
| Noctalia | `sans-serif` (default; no `font_family` in `settings.toml`) |
| Ghostty and herdr-app | `JetBrainsMono Nerd Font` by name |

Ghostty and herdr-app are the exception: they ask for the family by name, so
the terminal does not depend on the alias.

Base size 10pt (13px at 96 dpi), close to macOS's 13px. Hierarchy by weight
and size, never by color. Inter plays the role of SF Pro, which is only
licensed for Apple hardware; on the bar the regular Inter applies (not
Display), which is the small-size version, like SF Text. The bar follows the
macOS menu bar: on the left the workspace and the active window (the window in
bold, 700, like the app name on macOS); on the right the tray and extras, then
battery, network, bluetooth, volume, the control center button and the clock in
the macOS format in pt-BR (`sáb. 26 de set. 18:21`). Everything else stays at
the default weight.

## Motion

Tokens in `hyprland/hypr/animations.lua`:

| Curve | Type | Use |
|---|---|---|
| `standard` | bezier (0.2, 0, 0, 1) | In-place state change: border, fade, zoom |
| `decelerate` | bezier (0.05, 0.7, 0.1, 1) | Something entering: layer, workspace, fade in |
| `accelerate` | bezier (0.3, 0, 0.8, 0.15) | Something leaving: window close, fade out |
| `snappy` | spring, mass 1, stiffness 880, damping 59 | Window opening and moving |

| Duration | Value | Use |
|---|---|---|
| Short | 100 to 150 ms (`speed` 1 to 1.5) | Exit, border, fade |
| Medium | 250 ms (`speed` 2.5) | Entrance, workspace, layer |

Rules:

- Entrances decelerate; exits accelerate and are shorter than the entrance.
- On a spring curve, `speed` does not set the duration; stiffness and damping
  do. `snappy` is critically damped (ζ ≈ 1): it settles in about 200 ms without
  overshooting. Since Hyprland 0.56 springs need 2 to 3 times more stiffness
  than before ([discussion
  #15495](https://github.com/hyprwm/Hyprland/discussions/15495)).
- Workspaces switch with `slidefade 15%`: it slides a little, just enough to
  tell which side it came from.
- In Noctalia, `shell.animation.speed` is a multiplier. It is at 2.0, double
  the default, to keep up with Hyprland.
- **The shell animates itself.** The `shell-motion` layer rule
  (`windowrules.lua`) removes the Hyprland animation from the `noctalia-*`
  layers. With both on, the Hyprland fade stacked on top of the Noctalia
  animation, and the panel took about 40 ms longer to settle.

## Icons

- **App** (launcher, tray, dock, file manager): Papirus-Dark, from the
  `papirus-icon-theme` package.
- Who reads the theme: GTK (`settings.ini`), libadwaita apps (gsettings) and
  Noctalia (reads `gtk-3.0/settings.ini`). `.dotter/post_deploy.sh` adjusts
  the two that live outside the repo.
- **Shell glyphs** (Noctalia bar and panels): embedded Tabler font. The config
  chooses which glyph goes where (`launcher_icon`, `glyph` of the session
  actions), but the set does not change: Noctalia only loads the package's
  `noctalia-tabler.ttf`.

## Where each token lives

| Token | File | Written or generated |
|---|---|---|
| Palette and templates | `hyprland/noctalia/settings.toml` (defaults), `~/.local/state/noctalia/settings.toml` (each machine's choice) | Written (by the Noctalia UI, outside the repo) |
| Colors in Hyprland | `hyprland/hypr/noctalia.lua` | Generated, not used |
| Window border | `hyprland/hypr/borders.lua` | Written |
| Radius, shadow, gaps, blur off | `hyprland/hypr/look.lua` | Written |
| Shell opacity | `[bar]`, `[osd]`, `[shell]` and `[shell.panel]` in `settings.toml` | Written |
| Motion | `hyprland/hypr/animations.lua` | Written |
| Font family | `desktop/fonts/50-fonts.conf` | Written |
| Font and icons in GTK | `hyprland/gtk/gtk-{3,4}.0/settings.ini` | Written |
| Ghostty theme | `~/.config/ghostty/themes/noctalia` | Generated, outside git |
| herdr-app theme | `~/.config/herdr-app/themes/noctalia.json` | Generated, outside git |

`borders.lua` is the only place that defines border color. The generated
`noctalia.lua`'s `apply_theme()` is not called, because it would overwrite the
border.

`settings.toml` is rewritten whole by the Noctalia UI on every change. Edit
the file with the settings screen closed, otherwise one of the two writes is
lost.

## Bringing in a new app

1. Does the color come from the palette? If Noctalia has a template for it,
   enable it in `theme.templates`. If it is a terminal app, use an ANSI index.
2. Does the font come from the alias? Ask for `sans-serif`/`Sans` or
   `monospace`, never the family by name.
3. Are radius and spacing on the scale?
4. Does it have its own animation? Use the durations and curves from here.
5. Is it an exception? Record it below, with the reason.

## Recorded exceptions

| Where | What | Why |
|---|---|---|
| `windowrules.lua`, `pip-float` | Picture-in-Picture borderless and opaque | The video is the content; hairline and transparency get in the way |
| Ghostty `config` and herdr-app `settings.json` | Font family by name | Explicit choice, so the terminal does not depend on the alias |
| `look.lua`, shadow | Literal black | Shadow does not change color with the palette |
| `settings.toml`, `[bar.default] border` | `#ffffff14`, copy of `inactive_border` from `borders.lua` | Noctalia does not read Hyprland; the bar hairline has to match the window's |
| `keymaps.lua`, `SUPER+SHIFT+G` | Zeroes gaps, border and radius | Screen-sharing mode; restores the values from `look.lua` |
